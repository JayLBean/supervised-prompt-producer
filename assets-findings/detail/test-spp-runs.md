## 4. spp_mini — the API reimplementation (what it keeps, what it drops)

`spp_compare/spp_mini` reimplements the loop as discrete OpenAI calls
(`scripts/spp_agent_runner.py`, `optimizer.py`, `prompts/roles/{analyst,auditor}.md`)
to "hold the framework constant and vary only the optimizer brain" — isolating
framework-effect from optimizer-model-effect.

**Loop mechanics `[cited]`:**
- **One-field-per-iteration focus**: `pick_focus_field(val_eval, exclude_fields)`
  selects the largest weighted-gap T1 field each iter.
- **Analyst → Auditor gate → eval**: `call_analyst` proposes a `rewritten_prompt`;
  `call_auditor` returns approve/reject; a rejected edit gets **one-shot retry with
  auditor feedback**, then is dropped if still rejected.
- **Revert-on-regression**: `kept = delta >= -0.001` (marginal regressions absorbed as
  noise); on a real regression "regression > noise floor, REVERTED," keeping
  `last_accepted_prompts` (`spp_agent_runner.py:507–513`).
- **Plateau stop**: "stop after 2 consecutive val_composite deltas < 0.005, OR max 8
  iterations" (`auditor.md:19`, CLI `--plateau-delta 0.005 --plateau-window 2`).
- **Cost isolation**: optimizer spend on a separate OpenAI key (`OPENAI_API_KEY_2`) so
  the framework's own cost is measurable, not hidden in student spend.

**Conservatism mechanisms preserved:** all four — per-field focus, auditor-gate-
before-eval, revert-on-regression, plateau stop.

**Isolation guarantee dropped / weakened:**
- The auditor **is** score-blind here too: `call_auditor` receives only
  `target_group`, `focus_field`, `analyst_diagnosis`, `schema_contract`, the unified
  `diff`, and the two prompt **byte counts** — no F1/Jaccard, no eval.json
  (`spp_agent_runner.py:146–175` `[cited]`). The auditor role doc instructs "Default to
  approve when the edit is plausible and within scope… block clearly unsafe edits, not
  micro-manage" (`auditor.md:48`). So score-blindness is *preserved in form*.
- What is dropped is the **per-stage subagent boundary as a hard architectural lock**:
  analyst and auditor are functions sharing one process, distinguished only by their
  system-prompt + a narrowed user-payload, rather than isolated subagents with
  contract-enforced filesystem allow-lists. The discrepancy/rule-edit separation that
  shipped spp keeps as distinct stages is collapsed into a single analyst that reads
  errors *and* rewrites the prompt. So spp_mini demonstrates the *behavioral*
  conservatism without the *structural* isolation guarantees — exactly the
  "score-access concern → batch auditing, not score access" tension CLAUDE.md §8 warns
  about, but here the score-blindness is honored by construction even without the lock.

## 5. cross_evaluation / spp_compare — framework-effect vs model-choice

**Four-way comparison** (`spp_compare/FOUR_WAY_COMPARISON.md`,
`FRAMEWORK_JUSTIFICATION_REPORT.md`; 15-row DSpy seed-42 val; weighted soft-Jaccard
composite) `[cited]`:

| Config | Optimizer | Composite | Focus pass | All pass |
|---|---|---:|---:|---:|
| DSpy baseline (no opt) | — | 0.6921 | 3/15 | 9/31 |
| DSpy compiled (GEPA-light) | gpt-5.4-mini | 0.6770 | 3/15 | 9/31 |
| **spp_mini** | gpt-5.4-mini | **0.7297** | 2/15 | 8/31 |
| **spp_Opus / v6_frozen** | Claude Opus 4.7 (HITL) | **0.7321** | 5/15 | 11/31 |

**Conclusions `[cited]`:**
- **The spp win is a framework effect, not a model effect.** spp_mini beats DSpy
  compiled by **+0.0527 at the same optimizer model** (gpt-5.4-mini). "Same model,
  different framework → that's a framework effect."
- **Opus over spp_mini is +0.0024 on composite — inside the ±0.015 noise floor** — but
  Opus wins on the higher-tier discipline (focus_pass 5/15 vs 2/15; all_pass 11/31 vs
  8/31). The brain matters for the hard tail, not the headline.
- **Why DSpy/GEPA loses: no revert step.** "generate many, pick one" lets train-overfit
  candidates ship — 4/7 (B/C/D/E) groups regressed post-compile. "A revert-on-
  regression check (which both spp flows have) would have caught that."
- **Cost:** spp_mini optimizer-side $0.23 vs DSpy compiled $3.34 actual (~14×), and
  DSpy's own `run_metadata.json` under-reported its bill (only $1.20 logged — it hides
  reflection-LM traffic). End-to-end spp_mini ≈ $0.66 vs DSpy ≈ $5.00.

**Cross_evaluation** (`spp/cross_evaluation/REPORT.md`, 5 configs, 50 rows, re-scored on
v2 gold) `[cited]` adds the **schema-structure-vs-model-choice** decomposition on the
*same model*:
- On gpt-5-nano, the **v5 9-prompt (group-split) frozen prompt beats DSpy monolithic by
  +0.051** (0.6753 vs 0.6242) — pure prompt-architecture leverage, model held constant.
- The cross-**model** gap is smaller: gpt-oss-120b beats the best gpt-5-nano option by
  **+0.030** (0.7055 vs 0.6753).
- **Takeaway: schema/prompt structure is the larger lever than model choice here**
  (+0.051 structure vs +0.030 model), and both frameworks hit the *same* floor fields
  (`treatment_framing`, `product_wants`, `emotional_themes` stay at focus_pass 1/15
  across every model+architecture variant) — the ceiling is structural, not a model
  deficiency.

## 6. Bearing on the three planned spp directions

**(1) More prompting techniques — per-label/OvR, gated-boolean, anchored-CoT,
multi-prompt split.** The asset already instantiates the first three empirically:
- **Per-label binary (OvR)** is a *typed output_form in a shipped schema*:
  annotation-v2 `schema.json` marks 4 fields `per_label_binary` + 4
  `gated_per_label_binary` `[reproduced-by-us]` — concrete yes/no question batteries
  for the high-cardinality multi-label fields. A future spp prompting-technique layer
  could codify exactly this `output_form` enum.
- **Gated-boolean for default-attractor fields** is the `gated_*` forms +
  the 5 derived gate fields (`condition_named`, `causes_addressed`,
  `treatment_attitude_stated`, `drugs_mentioned`, `treatment_discussed`), each with its
  own threshold in `thresholds.yaml` and scored separately `[cited plan §2,§6]`. This
  is the "is-addressed boolean → conditional inner multi-label" fix for the
  default-attractor failure (Pattern A), already field-tested.
- **Multi-prompt / feature-group split** proven Pareto-better than monolithic (prior
  pass: +0.085 composite, 3× faster) and shown here to give +0.051 on a fixed model vs
  monolithic; the v4→v5 F-split/G-split (7→9 prompts) is the diminishing-returns
  frontier (v5 only +0.007 over v4).
- **Anchored-CoT for ordinals** is designed in the audit but **its benefit is
  unmeasurable** under the current exact-match metric — couples direction (3) to (1).

**(2) More statistical mechanisms.** Still absent and explicitly wanted. The
FRAMEWORK_JUSTIFICATION_REPORT admits bootstrap/permutation tests were not run; every
adjudication in this asset uses an informal point-estimate noise floor (±0.015) and
"Δ > 5× noise floor" / "inside noise" prose. The +0.0024 Opus-vs-mini tie and the
+0.0527 framework gap are *exactly* the comparisons a paired bootstrap CI would
formalize. Small-N fragility is acute and named in REPORTs: at n_dev=10–20 one row ≈
5–7 F1 points (35B REPORT: "1/15 ≈ 6.7 F1 points"); dev>test inversions are flagged as
noise, not overfitting. A significance layer would replace the heuristic gate and
directly serve these small-N regimes.

**(3) More supported modes (continuous/ordinal).** Confirmed again at the schema level:
**no target in either task is continuous or regression-typed.** The two ordinal fields
(`sentiment_intensity`, `journey_stage`) are squeezed into `single_select` exact-match
scoring — a ±1-step error scores identically to a max-distance error. There is no MAE,
RMSE, ordinal-distance, correlation, IoU, or span metric anywhere. `brand_mentions`
(`free_text`) is set-Jaccard, not string similarity. The ordinal fields are the live
demand signal; an ordinal/continuous mode would need a distance/MAE primitive, the
already-drafted anchored-CoT technique, and residual-distribution bookkeeping in
`eval.json`/REPORT.
