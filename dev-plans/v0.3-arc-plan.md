## §A. Where this arc comes from — the evidence in one screen

Three experimental assets converge on a small set of conclusions (full detail and
citation-tagging in `assets-findings/00-CONSOLIDATED-FINDINGS.md`):

- **The framework, not the model, is the lever.** spp-test: `spp_mini` beats the
  DSPy-compiled prompt by **+0.0527 at the same optimizer model** [reproduced-by-us];
  structure beats model choice (+0.051 group-split vs +0.030 model-swap). spp-ex: spp
  closes **68.3 % of the baseline→GEPA gap** (0.765 → 0.8306 [reproduced] of 0.861
  [cited]) — explicitly not a head-to-head win.
- **DSPy/GEPA fails for lack of a revert/audit gate.** 6 of 7 feature groups regressed
  post-compile [reproduced-by-us] — direct empirical support for spp's auditor and for the
  §7.1.3(e) "no search/auto-edit fusion" non-goal.
- **Feature-group splitting is the highest-value prompting structure, and spp already
  ships it** (+0.085 batched vs monolithic [reproduced-by-us]; the win is *the split*, not
  batching). "Multi-prompt split" must reconcile with the existing feature, not duplicate it.
- **The statistics gap is universal and already logged.** No bootstrap/CI/permutation
  anywhere; significance is an unsound fixed ±0.015 "noise floor" heuristic at dev sizes
  where one row ≈ 5 pp. `STATE-as-of-v0.2.0.md:107`: *"No bootstrap CIs / paired permutation
  tests on row-level scores … Cheap to add at finalize."*
- **Continuous/ordinal demand is real but latent.** Three ordinal fields are scored as flat
  categorical (documented "ordinal drift"); an anchored-CoT fix is drafted but unmeasurable
  without an ordinal-distance metric; PUPA's continuous leakage is folded into a binary
  composite. No asset holds a true continuous target — data would have to be introduced.

These map onto the three directions the maintainer asked to evaluate. The headline
recommendation (defended in §G) is to **open Direction 2 (statistics) first**: it is the
lowest-risk, already-logged change, and it is the measurement substrate the other two
directions need (you cannot tell whether OvR or anchored-CoT helped, at these dev sizes,
without significance).

### §7.1.4 (DRAFT) — Finalize-layer statistics (the measurement layer)

**What this layer is.** `spp` reports point estimates only. This layer adds inferential
statistics — a paired bootstrap confidence interval and a paired permutation test on the
per-row scores the loop already computes — so that a reported delta carries an honest
interval and a significance statement instead of an asserted constant noise floor. It is
the smallest change that closes a gap logged verbatim at `STATE-as-of-v0.2.0.md:107` and
flagged twice in the external comparison study (spp-ex report.qmd §4.4 item 7; FINDINGS §9).

**The load-bearing safety property: statistics are finalize-only.** A confidence interval
or p-value is a *score-derived* quantity — more score-derived than a raw score, not less.
It is therefore computed **only at `/spp-finalize`, only after the loop has terminated, and
is never written into any artifact a `/spp-loop` subagent reads.** Information flows
strictly loop → finalize; there is no return edge. This makes the statistics structurally
incapable of reaching the discrepancy, rule-edit, auditor, or adversary stages, which run
earlier with positive allow-lists that name their inputs. The auditor's score-access
prohibition (§4.2; invariant #2) is preserved verbatim and, if anything, reinforced: the
same reason `eval.json`/`results.json` are withheld from the auditor though they exist on
disk applies a fortiori to a CI.

**The sacred test set is still read exactly once.** The bootstrap **resamples the per-row
score vector already materialized by the single finalize read**; resampling is an in-memory
operation over an already-computed array of numbers. It does not re-run inference, does not
re-open the test partition, and introduces no preview or ranged-prediction surface
(invariants #6, #7 preserved verbatim).

**Statistics inform the human; they never gate the machine.** A CI or p-value must not
become an auditor input, a verdict-gate condition, or a confidence weight on a verdict
token. Verdict tokens stay categorical hard tokens with no confidence weighting (invariant
#14 preserved verbatim). The interval is surfaced to the human at G5 / REPORT §2 reading
time; the deterministic ship-decision tree's thresholds are unchanged in this layer
(whether a CI should ever qualify them is deferred — G-Q2).

**Scope boundary.** This layer is additive bookkeeping inside the existing
fixed-output-space methodology. It is neither a §7.1.2 enumerated roadmap item (it is not
multi-judge, multilingual, cross-model, or loop-resumption) nor a §7.1.3 deliberate
non-goal (it adds no selection signal to the loop and does not fuse proposal-with-selection).
It is closest in spirit to the v0.2 seven-bucket precedent: new finalize/metric-design
machinery, shipped standalone, with a no-statistics-present backward-compatible default.

**No new dependency.** The two estimators are implemented on the Python standard library
(`statistics`, `random`) plus the numeric stack already used by `eval.py`. `scipy` is
explicitly declined; if a future contributor argues for it, it carries a CLAUDE.md §8
justification and a CHANGELOG entry.

### Direction 1 — More prompting techniques

**Verdict per candidate** (citations from `assets-findings/detail/external-citations.md`):

| Technique | Verdict | Why |
|---|---|---|
| Feature-group / multi-prompt split | **reject-as-duplicate** | Already first-class (DESIGN §10, designer §5.0, `examples/feature-group-split/`); document, don't re-add. |
| Per-label binary / one-vs-rest (OvR) | **adopt as schema-metadata** | New `output_form`; six sections + all allow-lists untouched. Pre-validated in `hair-loss-annotation-v2`. (Tsoumakas & Katakis 2007; Zhang 2018) |
| Gated-boolean (is-addressed gate) | **adopt as schema-metadata** | Expressible in already-supported JSON Schema `if/then`; retires the "default-attractor" failure (Pattern A). |
| Anchored-CoT | **dev-confirmed hypothesis (inline only)** | Inline `<task>` form additive; the `raw_score`-field form is BREAKING **and** unmeasurable until Direction 3's ordinal metric. (Wei 2022) |
| CoT (general) | **dev-confirmed hypothesis (inline only)** | NOT the agentic/generation non-goal, but structure-affecting as a field/section. Sprague 2024 (arXiv:2409.12183): CoT weak on non-math classification — must earn its keep on dev. |
| Self-consistency | **defer** | Decoding mechanism; belongs to an inference/statistics arc; interacts with variance. (Wang 2022) |
| Few-shot (multi-shot) | **defer (BREAKING)** | Changes example-pair cardinality of the six-section structure (#12). (Brown 2020) |
| Least-to-most | **defer / reject** | Sequential dependency = cross-task composition (§10 boundary) + v1.0 compound-system arc. (Zhou 2022) |
| Prompt ensembling | **reject as fusion** | Nearest to §7.1.3(e); admissible only as user-owned downstream composition. (Arora 2022) |

- **Reconciliation (the explicit ask):** "multi-prompt split" duplicates the existing
  feature-group split at the orchestration layer → reject-as-duplicate. The only net-new
  surface is the **within-prompt** OvR / gated-boolean `output_form` metadata. Sequential
  and ensemble variants collide with the §10 cross-task-composition boundary and the
  forwarded v1.0 compound-system arc — keep them there.
- **Proposed scope (the additive arc):** first-class `output_form` values
  (`per_label_binary`, `gated_per_label_binary`, `gated_single_select`); gated-boolean via
  JSON Schema `if/then`; a DESIGN §10 / designer §5.0 note distinguishing within-prompt
  output shapes from between-prompt splitting. **Explicitly out:** CoT/anchored-CoT as a
  field, multi-shot few-shot, in-loop ensembling (each needs its own design pass).
- **Target version (proposed):** **v0.4 standalone** additive output-form arc (§7.1.2
  books v0.3 for multi-judge + multilingual; stapling output-forms onto that muddies it).
  The BREAKING items remain unscheduled pending their own design PRs.
- **Roadmap-vs-non-goal:** OvR / gated / inline-CoT = roadmap (additive, inside the fixed
  output space). Least-to-most / ensembling = non-goal-adjacent (composition / fusion).
- **Locked invariants touched:** additive scope leaves all untouched **except** #8 and #12,
  which are **at-risk only for the deferred BREAKING items** (CoT-as-field, multi-shot).
- **Open questions:** D1-Q1 ship output_form standalone vs behind the K>1 runner? D1-Q2 is
  OvR a new schema keyword or a scoring/parsing convention on `type: array`? D1-Q3
  anchored-CoT-field — co-schedule with Direction 3 or defer? D1-Q4 add a documented
  dev-confirmation discipline for inline CoT? D1-Q5 where is the within- vs between-prompt
  boundary documented so "multi-prompt split" is not re-added?

### Direction 2 — More statistical mechanisms  *(recommended first arc — see §C)*

- **What to add:** paired bootstrap CI + paired permutation test on the per-row **test
  delta** (headline); per-field **dev** CIs as diagnostics. All on the per-row score vector

- **Where it lands:** `/spp-finalize` step 4 + `metric-design` (review-and-record). REPORT

- **Target version (proposed):** a co-shipped **additive finalize bucket** (the §C arc);

  compound-system arc — but explicitly **not** part of the §7.1.2 v0.3 multi-judge design
  pass. Not big enough for its own version.
- **Roadmap-vs-non-goal:** neither §7.1.2-as-listed nor a §7.1.3 non-goal; an
  explicitly-logged forwarded gap (STATE:107). Additive, roadmap-flavored.
- **Locked invariants touched:** **all 21 UNTOUCHED** — the point of the finalize-only
  placement. The one to watch in review is #14 (no CI-as-gate).
- **CHANGELOG:** additive (`### Added`), "No new dependencies," methodology note that
  statistics are finalize-only and gate nothing. Not BREAKING.
- **Open questions:** D2-Q1 does the CI ever inform the ship-decision tree, or stay
  descriptive (recommend descriptive in v1)? D2-Q2 seed policy (fixed vs derived from

### Direction 3 — More supported modes (continuous / ordinal / regression)

- **The explicit ruling:** **roadmap generalization, NOT a non-goal.** §7.1.3(a) bites only
  on *unbounded generation with no correct label* (`DESIGN.md:2026-2036`). Ordinal and
  regression targets have ground truth and a bounded/single answer per row → inside the
  fixed-output-space boundary; confirmed by the `number → MAE/RMSE` spec (`DESIGN.md:723-726`).
  Proposed as a **one-sentence DESIGN clarification** (fixed-output-space = ground-truth
  presence, not metric family), not a reclassification — continuous was never a non-goal.
- **Two sub-modes, ordinal first.** Sub-mode A (bounded ordinal: the 3 real spp-test fields)
  needs only an `ordinal_distance` metric + an `ordered`-enum marker, stays in the
  `[0,1]`-higher-is-better family, and **unblocks the already-drafted anchored-CoT** (couples
  to Direction 1). Sub-mode B (regression) needs a new numeric inference/scoring path,
  MAE/RMSE, residual-based discrepancy, and a fixture introduced — heavier, no in-asset target.
- **The hard open question (auditor judgment):** "categorical vs row-specific" is well-defined
  for a discrete label but not for "predict 0.5 lower when X." **Option 1** (recommended):
  reframe the existing binary verdict as "same directional/magnitude adjustment on a class of
  rows" — preserves the hard-token contract (#14) and gate matcher (#8). **Option 2**: new
  numeric-edit verdict tokens — BREAKING against #8 and #14; only if Option 1 fails a dry-run.
  Under both, the auditor stays **score-blind**: per-row residuals are score signal, withheld.
- **Target version (proposed):** **v0.5 or later** — heaviest direction; reshapes the
  auditor's core judgment; depends on the K>1 runner actually existing and on Direction 2's
  per-row retention. Opens with its own `docs(design): pin` + ~7 buckets; the auditor reframe
  is the bucket to pin most carefully.
- **Locked invariants touched (highest surface of the three):** #14 **at-risk (highest)**;
  #2 at-risk (must hold — residuals are score signal); #8 shape-change under Option 2; #13,
  #1 (content-shape only), #5 shape-change; #6/#7/#12 untouched.
- **Open questions:** D3-Q1 (lead) Option 1 vs Option 2 for the auditor reframe? D3-Q2
  prescribed resolution when an aggregate mixes F1 and MAE (force `min`/normalized, or numeric
  field on its own floor)? D3-Q3 ordinal-first sequencing, and may ordinal ship before the
  full K>1 runner?

## §G. Ranked recommendation (leverage vs invariant risk)

1. **Open Direction 2 (finalize-layer statistics) first.** *Highest leverage-to-risk
   ratio.* All 21 invariants untouched; already logged as "cheap to add at finalize"; it
   directly answers the external study's own flagged gap; and it is the measurement
   substrate the other two directions require — at dev sizes where one row ≈ 5 pp, neither
   an OvR change nor an anchored-CoT change can be judged real without a CI. This is the §C
   seven-bucket arc.
2. **Then Direction 1's additive output-form metadata (OvR, gated-boolean).** Proven
   leverage (the +0.085 split win; forms already validated in `hair-loss-annotation-v2`),
   additive schema-metadata, no isolation or six-section change. **Defer** CoT-as-field,
   multi-shot few-shot, and in-loop ensembling as BREAKING items with their own design PRs.
   Proposed target v0.4.
3. **Later, Direction 3 — ordinal sub-mode first.** It retires a documented failure on three
   real fields and unblocks anchored-CoT, but it reshapes the auditor's core judgment (the
   single hardest open question in the whole program) and depends on the K>1 runner and on
   Direction 2's per-row retention. Proposed target v0.5+; regression sub-mode after.

Rationale in one line: **do the cheap, isolation-safe measurement layer first; it de-risks
everything downstream and is owed already.**
